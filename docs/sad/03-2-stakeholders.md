### 3.2 Stakeholders and Concerns

| Stakeholder | Goals and concerns | Responsibilities and system interactions |
|---|---|---|
| Citizen | Submit and track waste collection requests, cancel before a request is Scheduled, and receive status notifications. Personal data and home-location confidentiality are security objectives (SCW-SO-1). | Registers and logs in, submits a request with its location, waste type, estimated quantity and optional photo, tracks status, cancels an eligible request, and receives in-app/email notifications through the Web Frontend. |
| Collection Vehicle Driver | View the assigned route as ordered stops on a map and record whether stops are Collected or Missed. | Uses the Web Frontend to view the assigned route and mark stop outcomes; stop updates are handled by the Route Optimization Engine and update request status. |
| Admin / Municipal Officer | Manage collection operations and access operational status, reports and route generation. Integrity and accountability of request, route and facility data are security objectives (SCW-SO-2). | Uses the Web Frontend to view, filter, approve and reject requests; override request priority; manage vehicles, facilities and user accounts; generate routes; view the dashboard; and export daily collection reports as CSV. Admin actions are written to the audit log (SCW-SEC-006). |
| Disposal Facility Operator | Record incoming waste and manage facility capacity. | Uses the Web Frontend to record incoming waste by vehicle and weight; the Facility Service updates remaining capacity. |
| Municipal officers (client / product owner) | Confirm that the system requirements meet municipal needs. | Review and confirm the requirements and intended waste-collection workflow. The project context does not specify an individual municipal representative or approval process. |
| Team 04 developers, architects and testers | Implement the agreed design and verify it against the SRS and Test Plan. | Develop and test the system using the documented components, APIs and requirement traceability. The project context identifies Sonu Akash as lead / integrator and the other members as team members, but does not assign further system-operation responsibilities to individual members here. |
| Course instructors / evaluators | Assess the completeness and quality of the project deliverables. | Review the SRS, SAD and Test Plan; they do not have a specified operational role in the deployed system. |
| OpenStreetMap and SMTP email provider | Provide external map and geocoding services and email delivery on which parts of the system depend. | OpenStreetMap supplies map tiles and geocoding; the SMTP email provider sends status-change email notifications. If either service is unavailable, map display or email delivery may be degraded; in-app status tracking continues. The project context does not define provider service levels or additional responsibilities. |

The system uses a layered (3-tier) architecture: the Web Frontend presents role-appropriate functions, FastAPI services implement application behavior, and PostgreSQL stores persistent data. The project context does not further specify stakeholder decision rights, municipal approval arrangements, or external-provider service agreements; those details require confirmation if needed for implementation or operation.
